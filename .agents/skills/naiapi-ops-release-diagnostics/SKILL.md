# Ops, Release, and Diagnostics

Use this skill for operational build surfaces, release packaging, deployment config, Docker/compose files, CI workflows, embedded frontend dist behavior, Electron packaging, metrics, logging, health diagnostics, and troubleshooting build/runtime startup failures.

## Authority Map

- `main.go` for embedded `web/default/dist` and `web/classic/dist` requirements, startup tasks, cron-like services, and route bootstrap.
- `Dockerfile`, `Dockerfile.dev`, `docker-compose.yml`, and `docker-compose.dev.yml` for runtime and local stack behavior.
- `.github/` workflows and repository health files for CI/release expectations.
- `web/default/package.json`, `web/classic/package.json`, and frontend dist build scripts when backend embedding changes.
- `setting/performance_setting/`, `controller/performance.go`, `service/`, logs, and metrics packages for runtime diagnostics.
- `electron/` when desktop packaging or embedded-web behavior is involved.

## Operating Rules

- Preserve protected project identity metadata and attribution in README, package metadata, Docker labels, license, and release files.
- Backend builds that include `main.go` require embedded frontend dist paths to exist or be generated by the build pipeline.
- Treat missing dist files, sandbox-bound ports, and local dependency gaps as environment baselines unless a code diff causes them.
- For CI or container changes, keep SQLite, MySQL, PostgreSQL, and Redis assumptions explicit.
- For diagnostics changes, keep log content useful without leaking secrets, API keys, or user tokens.

## Validation

Use the narrowest command that exercises the changed surface:

```bash
GOCACHE=/private/tmp/naiapi-gocache go test ./setting/config ./setting/model_setting ./setting/operation_setting ./common
```

For frontend packaging, run the relevant Bun build/typecheck script from the frontend root and record current baseline failures separately from introduced regressions.
